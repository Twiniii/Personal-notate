# Personal-notate — ЛР №7–9

Типізований CRUD-сервіс персональних нотаток: узагальнення, колекції та сортування. Продовження ЛР №6 зі збереженням текстових нотаток, списків справ і покупок, форматів показу та обробки помилок.

## Запуск

Потрібен JDK 25. Відкрийте CMD або PowerShell у папці проєкту, де розташована папка `src`:

```powershell
chcp 65001
javac --release 25 -encoding UTF-8 -d out -sourcepath src src\Main.java
java -cp out Main
```

Maven та зовнішні бібліотеки для цієї версії не потрібні. Папка `out` створюється компілятором і не завантажується в Git.

## Користування

Введіть номер дії та натисніть Enter. Меню працює до вибору 0.

| Пункт | Дія |
| --- | --- |
| 1 | Додати одну або декілька нотаток |
| 2 | Показати назви та ID |
| 3 | Знайти й порахувати за пріоритетом |
| 4 | Показати копію за пріоритетом |
| 5 | Знайти за повним збігом вмісту |
| 6 | Відкрити нотатку за ID |
| 7–8 | Змінити або порівняти формати показу |
| 9 | Поточна кількість та історія додавань за сеанс |
| 10–11 | Демонстрація наслідування та підказка для типу |
| 12 | Оновити нотатку за ID |
| 13 | Видалити нотатку за ID |
| 14 | Показати копію за назвою |
| 15 | Показати копію за назвою, потім пріоритетом |
| 16 | Демонстрація CRUD, узагальнень і сортування |
| 17 | Каталог категорій: додавання, пошук, оновлення, видалення та сортування |
| 0 | Вийти |

Нотатка має назву, текст, категорію та пріоритет 1–10, де 1 — найвищий. Назва не може бути порожньою. TextNote додатково має джерело; ChecklistNote — пункти та стани виконання; ShoppingListNote — також магазин. Enter завершує введення поля. За один раз можна додати до 100 нотаток, а загальна кількість у колекції не обмежена цим числом.

ID видається автоматично й не змінюється після сортування. Оновлення замінює всі поля об’єкта з тим самим ID, не збільшуючи кількість. Невдале оновлення зберігає попередній запис. Видалення повертає true, якщо запис був, і false, якщо його вже немає. При виборі ID число 0 повертає назад.

**Дані зберігаються лише в пам’яті одного запуску.** Після виходу вони втрачаються. Каталог категорій поки незалежний від тексту категорії в нотатці: перейменування каталогу не переписує нотатки. Observer рахує додавання за сеанс, а не поточний склад після всіх оновлень і видалень. Демонстрації не змінюють користувацькі дані.

## Контракт і типізація

```java
T findById(long id);
void save(T entity);
boolean delete(long id);
List<T> findAll();
List<T> findAllSorted(Comparator<? super T> comparator);
```

CRUDService також має default-метод `findAllSortedByName()`, який викликає `findAllSorted(EntityComparators.byName())`. У наданій текстовій методичці сигнатури каркаса після його заголовка не відображалися; наведений контракт реалізує її словесні вимоги, з обраним `void save(T entity)`.

`T extends BaseEntity` гарантує getId/getName без приведення типів. Той самий InMemoryCrudService працює з Note та Category. Поля id/name у BaseEntity — private final; ID додатний, назва непорожня. При оновленні створюється новий об’єкт зі старим ID.

`NoteService extends CRUDService<Note>` додає `findAllSortedByNameAndByPriority()`. Пріоритет є лише у нотаток, тому метод не належить загальному сервісу. Його реалізація також викликає findAllSorted, передаючи компаратор `comparing(...).thenComparingInt(Note::getPriority)`.

`Comparator<? super T>` дозволяє передати компаратор T або його базового типу: наприклад, Comparator<BaseEntity> для нотаток. `Collection<? extends BaseEntity>` у printAll дозволяє читати колекції будь-яких підтипів як BaseEntity. List<Note> не є List<BaseEntity>, бо інакше в нього можна було б додати Category. Wildcard дозволяє читання, але не додавання довільного BaseEntity.

## Сховище та складність

Обрано `LinkedHashMap<Long, T>`: ключ — ID, пошук швидкий, порядок додавання передбачуваний. `put` додає новий ключ або оновлює наявний, не змінюючи його позиції. `findAll` повертає новий ArrayList із значеннями Map.

n — кількість записів, c — місткість HashMap. Для хеш-таблиць O(1) є очікуваною/амортизованою оцінкою. Вартість порівняння рядків залежить також від їхньої довжини.

| Колекція | findById | save за ID | delete за ID | Новий список за назвою | Порядок |
| --- | --- | --- | --- | --- | --- |
| ArrayList | O(n) | O(n), пошук ID | O(n) | O(n log n) | Позиції списку |
| HashMap | O(1) очікувано | O(1) амортизовано | O(1) очікувано | O(n + c + n log n) | Не гарантований |
| LinkedHashMap | O(1) очікувано | O(1) амортизовано | O(1) очікувано | O(n log n) | Додавання |
| TreeMap за ID | O(log n) | O(log n) | O(log n) | O(n log n) | Ключі-ID |

TreeMap за ID не дає сортування за назвою. ArrayList потребує лінійного пошуку при upsert. Таблиця описує сам generic-сервіс: допоміжні перевірки в Notebook і getNoteCount через findAll мають O(n).

## Порівняння та винятки

Обрано Comparator, бо потрібно кілька порядків: назва, назва/пріоритет і пріоритет. Comparable закріпив би лише один природний порядок у моделі. Назви порівнює Collator для uk-UA; пріоритет порівнюється чисельно тільки при рівних назвах.

BaseEntity.equals/hashCode final і залежать лише від ID. Один генератор видає ID для нотаток і категорій. При ручному створенні об’єктів не слід призначати однакові ID різним сутностям. Перевірку всіх полів попередньої версії винесено в hasSameContent, тому пошук за вмістом збережений.

Компаратори за назвою **не узгоджені з equals за ID**. Різні ID з однаковою назвою можуть дати compare == 0. Для сортування List це нормально: усі записи зберігаються. TreeSet із таким компаратором міг би відкинути запис із такою самою назвою. Тому він не використовується як сховище.

Методи сортування створюють новий список і не змінюють Map. Копії поверхневі: містять посилання на незмінні сутності. Старий список залишається знімком навіть після заміни об’єкта через save.

EntityNotFoundException — RuntimeException з id. Меню перехоплює його конкретним catch, а проміжні методи не потребують throws. Відсутній findById порушує очікування отримати сутність; для delete відсутність — звичайний false. save(null) відхиляється через Objects.requireNonNull.

## Перевірка

Після компіляції основного коду:

```powershell
javac --release 25 -encoding UTF-8 -cp out -d out tests\CrudServiceChecks.java
java -cp out CrudServiceChecks
```

Очікуваний результат: `Успішних перевірок: 76`.

Для демонстрації оберіть пункт 16. Він створює три записи: ID 101 — «Плани», пріоритет 8; ID 102 — «Покупки», 3; ID 103 — «Плани», 2. За назвою результат 101, 103, 102; за назвою/пріоритетом — 103, 101, 102. Порядок сховища залишається 101, 102, 103. Оновлення зберігає кількість 3; відсутній ID дає виняток; повторне видалення повертає true, потім false. Той самий generic-клас показано для категорій.

Перевірено на Linux із JDK 25: компіляція та 76 перевірок. Папки результатів і дані не входять в архів. Гілка за критеріями об’єднаного завдання — `lr7/personal-notate`, PR — у `main`.
